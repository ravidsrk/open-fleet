# Distribution, Discoverability & Packaging

[Documentation Hub](README.md) · [Install](install.md) · [Maintainer Ops](ops.md)

This reference covers how `open-fleet` is packaged for distribution, its enforced vs. observed runtime pins, self-contained bundle generation (`dist/`), and external directory listing status. For step-by-step installation instructions, use **[Install](install.md)**.

## Evidence boundaries in public listings

When describing `open-fleet` in external directories or release notes, distinguish between static catalog checks and live run verification:

- **Static catalog checks (`validate.py`, `run_report.py`):** Enforce `agentskills.io` frontmatter, three-layer separation, badge freshness, and SHA-256 inventory bindings for retained runs in **[docs/runs/README.md](runs/README.md)**. Currently the catalog holds **2 external-run**, **3 self-run**, and **17 doctrine-only** missions.
- **Off-worker live verification (`verify.py` + coordinator):** During a mission run, `verify.py` verifies frozen scope, git ancestry on `BASE`, GitHub review freshness, and negative-control replay (`--execute-nc --nc-command`), while the coordinator runs the clean-environment test suite at `head_sha`, the ≥ 10% control sample, and post-deploy revision verification.
- **In-session native hooks (`verify-gate.sh`):** Provide local defense-in-depth inside a worker session; full soundness requires off-worker execution (CI, MCP Task, or coordinator subprocess — see [Trust boundary](verify-gate.md#trust-boundary)).

## Self-containment: what a single copied mission loses

In the source repository, `skills/<name>/SKILL.md` references its phase playbooks (`playbooks/`) and runtime policies (`runtime/`) by bare name and links to `../../ARCHITECTURE.md`. Copying a single `skills/<name>/` folder out of the source tree severs those relative paths.

`scripts/bundle.py` solves this for copy-based installers and the lean plugin:
- Every `dist/skills/<name>/` folder carries a vendored `references/` directory containing all composed playbooks, transitive runtime policies, `ARCHITECTURE.md`, and a generated `references/README.md` index, plus `runtime/scripts/` and runtime control JSON files (`pins.json`, `one-way-doors.json`, `quarantine.json`).
- Outbound links in the bundled `SKILL.md` are automatically rewritten to point into `references/`.
- At the bundle root, `scripts/bundle.py` also ships `.claude-plugin/bundle-README.md` as `README.md`, `.claude-plugin/icon.png` (1024 px square PNG listing icon), `LICENSE`, `THIRD_PARTY_NOTICES.md`, and `hooks/hooks.json`.
- Bundled helpers expect `OPEN_FLEET_ROOT` exported to the installed mission directory. Always point copy-based registries and plugin directory submissions at the published `dist` branch, never at `skills/<name>/` on `main`.

## Prerequisites, pinned

`scripts/install.sh` separates **install** prerequisites (hard requirements to link and validate the catalog) from **run** prerequisites (warned at install time; when a mission starts, `preflight.py` enforces `gh` and the runtime's capabilities, while Orca pin drift is only a `spawn_worker.sh` NOTE):

| Prerequisite | Class | Enforced requirement | Witnessed baseline |
|---|---|---|---|
| `git` | Install | Required (hard fail if absent) | 2.47.3 (clean container), 2.55.0 (macOS host) |
| `python3` | Install | ≥ 3.11 (hard fail below 3.11; CI tests 3.11, 3.12, 3.13) | 3.13.15 |
| Orca app + CLI (or RPI runtime) | Run | Orca ≥ `runtime/pins.json` pin, currently **v1.4.239** (soft warn on install; `validate.py` enforces pin agreement), or `OPEN_FLEET_RUNTIME=posix` | v1.4.239 source-delta re-witness with live 1.4.239 receipts (2026-10-26) + macOS/Linux live witnesses ([`pins.json`](../runtime/pins.json)) |
| `gh` (authenticated) | Run | Present + `gh auth status` green (soft warn on install) | 2.100.0 |
| Coding-agent harness | Run | Claude Code (`claude`) or supported harness in [runtimes.md](runtimes.md) | Claude Code 2.1.272+ |

Clean-container installation is verified in CI on every install-path PR ([`.github/workflows/install.yml`](../.github/workflows/install.yml) · [clean-container transcript](completion/evidence/414-clean-container-install.txt)).

Validating `main` timed out twice on 2026-10-25 and would ship every receipt tree to each install.

- **1 blocking:** *README missing*. The bundle had no README in the plugin folder. `scripts/bundle.py` now ships `.claude-plugin/bundle-README.md` there as `README.md`, so the next release's `dist` clears it. Re-validate after that cut before submitting.
- **13 policy holds** for a reviewer:
  - *Uses a credential from the user's machine*: `upstream_probe.py` sends `GITHUB_TOKEN` to `api.github.com`; `deny-hook.sh` pairs `$PWD` with its `probe.invalid` self-test string; and `offload-it`'s `GH_TOKEN` is read beside a negative-control `nc` the scanner took for netcat;
  - the file count;
  - `verify-gate.sh` running other files.
  The bundle README (`.claude-plugin/bundle-README.md`) discloses each one. None blocks.
- **26 warnings:** download-and-run commands, which in shipped code are the guard hook's own deny patterns, and *No icon*.
