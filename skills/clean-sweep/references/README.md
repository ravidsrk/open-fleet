# `clean-sweep` bundled references

Generated by `scripts/bundle.py`. In the repository these live in `playbooks/` and
`runtime/`, two directories above the mission. An installer that copies skill
directories out of the tree severs that path, so the copies live here instead —
resolve bare protocol names throughout the mission and its protocols against this list.

## Installed runtime

Set `OPEN_FLEET_ROOT` to the absolute installed mission directory (the directory
containing SKILL.md). Run commands from the PROJECT repository being worked on;
keep manifests, contracts and other project paths relative to that repository.
These protocols already name their runtime as
`"$OPEN_FLEET_ROOT/runtime/scripts/<file>"`, so export that variable and run the
commands as written; no path is left to substitute by hand. Runtime JSON lives under
`"$OPEN_FLEET_ROOT/runtime/"`; helpers locate it relative to themselves.
Read the mandatory `docs/runs/TEMPLATE.md` from
`"$OPEN_FLEET_ROOT/docs/runs/TEMPLATE.md"` ([run-report template](../docs/runs/TEMPLATE.md));
write the filled report and its evidence into the PROJECT repository.
Follow its target-project gates and integrity inventory procedure. The separate
catalog proof-promotion section applies only in an open-fleet catalog clone;
recording an external run does not promote the installed mission's proof tier.
Python 3, a POSIX shell and git are host prerequisites; live operations also
require the external tools and permissions named by their protocols (Orca, gh, etc.).

```sh
python3 "$OPEN_FLEET_ROOT/runtime/scripts/verify.py" --help
python3 "$OPEN_FLEET_ROOT/runtime/scripts/evidence-run.py" --help
python3 "$OPEN_FLEET_ROOT/runtime/scripts/preflight.py" --help
```

[Payload inventory](bundle-files.json) lists every required installed file.
